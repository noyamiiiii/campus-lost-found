# ADR 0001：单仓多应用与技术选型

| 项 | 内容 |
| --- | --- |
| 状态 | 已接受（运行时版本待团队复核） |
| 日期 | 2026-10-30 |
| 决策人 | 项目组 |
| 相关文档 | `docs/decisions/day0-decisions.md` |

## 背景

课程项目需要同时交付前端、后端、AI 服务、部署脚本和全套设计文档。团队 4 人，均为学生，时间碎片化，评审需要能一次拿到全部材料。

## 决策

1. **单仓多应用（monorepo）**：`frontend/`、`backend/`、`ai-service/`、`deploy/` 同仓管理，文档与代码同仓演进。
2. **运行时版本**：
   - 后端 JDK 21 + Spring Boot 3.5.x（LTS 版本，课程机与本机已验证可运行）。
   - 前端 Node.js 22 + pnpm 11 + Vue 3.5 + Vite 6。
   - AI 服务 Python 3.13 + FastAPI；向量计算在 W8 再引入，W1 只保留健康检查。
   - 中间件 MySQL 8.4、Redis 7.4、MinIO 固定 tag，不使用 `latest`。
3. **前端不直连数据库与 AI**：浏览器只访问后端 API；后端再调用 AI 服务。AI 服务只返回向量与候选结果，业务判定留在后端。
4. **接口契约先行**：`contracts/openapi.yaml` 是前后端唯一依据，字段变更先改契约再改代码。

## 备选方案

| 方案 | 放弃原因 |
| --- | --- |
| 前后端分仓 | 课程评审需要跨仓找材料；接口变更同步成本高 |
| 后端单体包含 AI（Python 内嵌） | 与团队技能不匹配，图像依赖重，部署体积大 |
| 前端直连 AI 服务 | 暴露服务地址，鉴权与限流无法统一 |

## 后果

- 好处：一次 clone 拿到全部材料；契约与文档同仓，评审友好；CI 可统一跑三端检查。
- 代价：仓库体积增大，需要 `.gitignore` 与目录约定约束；三人同时改根目录文件时容易冲突，根目录文件变更需在群里知会。
- 风险：Maven 4 仍为 RC，后端构建以 Maven 3.9 为基线。若团队机器只有 Maven 4，统一使用 IDEA 内置 Maven。

# 文档索引

| 目录 | 放什么 | 什么时候产出 |
| --- | --- | --- |
| `decisions/` | Day 0 决策、周会结论、范围变更 | 第 1 周起持续更新 |
| `adr/` | 架构决策记录（ADR），一次决策一个文件 | 议题出现当周 |
| `requirements/` | D1 需求规格、D2 设计规格、范围表 | W3–W5 |
| `diagrams/` | 用例图、活动图、状态图、ER、类图、时序图、部署图、PAD | W4 起持续 |
| `prototype/` | 原型截图、页面说明、交互备注 | W4 起 |
| `meetings/` | 评审记录、问题清单、待办 | 每次会议后 24 小时内 |
| `test/` | 测试计划、用例、缺陷、验收记录 | W7 起 |

## 命名约定

- 日期前缀统一 `YYYY-MM-DD`，例如 `2026-11-06-w4-review.md`。
- 图文件与正文同名，例如 `use-case.puml` / `use-case.svg`。
- 文档标题下必须写：版本、作者、最后更新日期、变更摘要。

## 写作原则

1. 先写结论，再写依据；评审者只有 5 分钟。
2. 每个“待定”必须带负责人和截止日期，否则视为未完成。
3. 图表源文件与导出图一起提交，导出的 PDF/SVG 放同目录。
4. 需求变更只改一处：`requirements/scope.md`，其余文档引用它。
